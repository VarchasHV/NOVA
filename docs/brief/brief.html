Yugaantar 2026 · DevForge · Track 1 “Can It Play DOOM?” · Project brief

BBB (Bictor Bon Boom): Budgeted, Position-Anchored
Spatial Memory for Zero-Shot DOOM Play

Team NOVA
github.com/VarchasHV/NOVA
Abstract. We present BBB (Bictor Bon Boom), a 1.07 M-parameter recurrent agent that plays unseen DOOM levels from ego-centric telemetry alone. The core of BBB is a Streamed Memory: a fixed budget of 32 slots, each anchored to a pose that the agent estimates for itself with a learned odometry network. New slots are streamed in when the agent enters unmapped space, and the least relevant slot is streamed out when the budget is full. The memory is read by attention conditioned on each slot’s distance and bearing from the agent’s current pose. The design follows how open-world games keep a bounded set of world chunks loaded. The agent is trained from scratch with our own recurrent PPO, an asymmetric privileged critic, a reward aligned with the official scoring categories, and a curriculum over procedurally generated and solvability-checked maps. On two sets of about 250 held-out episodes across all four tiers, the submitted checkpoint reaches the exit in 65–73 % of them and deliberately collects keys and opens locks in long-horizon levels. Wiping its memory at every step lowers the score by 50 points (95 % CI 36–65). A decision takes under 1 ms on one CPU thread.

1 Introduction

Agents trained on a fixed set of levels tend to memorise button sequences and fail when a wall moves [7, 8]. The DevForge suite, built on ViZDoom [1], tests zero-shot play on unseen maps in four tiers: combat, multi-room exploration, key-and-lock progression, and a full gauntlet. Under partial observability, the hard part is to remember where things are: a locked door passed three rooms ago, or a branch that was a dead end. The observation contains no global coordinates. A GRU must compress that history into one vector. External memories such as Neural Map [5] usually assume a known position. BBB (Bictor Bon Boom) instead builds its own estimate of where it is and organises memory around that estimate.

Contributions.

  • Streamed Memory, a position-anchored slot memory with a fixed budget, learned gated writes, learned eviction by relevance, and reads conditioned on geometry (§2.2).
  • Neural odometry that turns ego-centric rays and velocities into a spawn-frame pose, so the agent anchors memory without any privileged input at test time (§2.1).
  • A complete training pipeline written from scratch: recurrent PPO with an asymmetric critic, a scorer-aligned two-stream reward, and a curriculum over solvable procedural maps with replay of failed seeds (§3).
  • A careful evaluation on about 250 held-out maps, with paired bootstrap confidence intervals and memory ablations (§4).

2 Method

Observation encoding. The 64 rays cover 360°, so we encode them with a 1-D CNN that uses circular padding. Up to 32 visible entities pass through masked set self-attention, which handles any number of enemies, followed by mean and max pooling. Vitals and the previous action go through an MLP. The three embeddings are concatenated, normalised and projected to \(x_t\in\mathbb{R}^{256}\). All scaling is fixed, so preprocessing is identical in training and in the submission.

2.1 Neural odometry.

The wrapper exposes neither heading nor position. A small circular CNN over the current and previous rays, together with the ego-frame velocity and the last three actions (because vanilla turning accelerates), predicts the motion \((\Delta f,\Delta r,\Delta\theta)_t\). Summing it gives the pose estimate

$$\hat\theta_{t+1}=\hat\theta_t+\Delta\theta_t,\qquad \hat p_{t+1}=\hat p_t+R(\hat\theta_t)\,[\Delta f_t,\Delta r_t]^\top .$$
(1)

Odometry is supervised with the true motion, taken from engine state, during a 60-update random-walk warm-up and then alongside PPO. At test time it sees only official observations. Heading error is about 0.1° per decision.

2.2 Streamed Memory.

The memory holds \(K=32\) slots \((c_j, p_j)\) with content \(c_j\in\mathbb{R}^{64}\) and an anchor \(p_j\) in the agent’s own spawn frame. A learned relevance \(\rho_j=\mathrm{MLP}(c_j,\text{age}_j,\text{visits}_j)\) scores each slot. Stream in: if no slot lies within \(r=320\) map units of \(\hat p_t\), a slot is allocated at \(\hat p_t\). When the memory is full, the new slot replaces \(\arg\min_j\rho_j\). Write: otherwise the nearest slot is updated with a learned gate,

$$c_j\leftarrow c_j+g_t\big(\mathrm{GRUCell}(w_t,c_j)-c_j\big),\quad g_t=\sigma\!\big(W_g[w_t;c_j]\big).$$
(2)

Read: each slot is seen from the current pose through \(\phi_j=(d_j,\log d_j,\sin\beta_j,\cos\beta_j)\) (distance and bearing). The slot is read with four-head attention,

$$\alpha_{j}=\mathrm{softmax}_j\!\Big(\tfrac{q_t^\top k_j}{\sqrt{d}}+\log\sigma(\rho_j)\Big),\;\; k_j,v_j=f([c_j;\phi_j]),$$
(3)

where the query \(q_t\) comes from \(x_t\) and the previous core state. The readout \(m_t=\sum_j\alpha_j v_j\) (128-d) and \(x_t\) feed a GRU core (256), which drives factorised categorical heads (move, strafe, turn, attack, use, weapon) that map to the nine buttons. Relevance biases the reads, so the policy gradient raises the relevance of useful slots, and those slots survive eviction. Allocation is a single distance threshold. Everything that is written, kept and read is learned. A fallback mode (memory_mode: soft) replaces the threshold with learned soft addressing.

3 Training

Recurrent PPO [2] is our own implementation, not a library. It uses sequence minibatches (truncated back-propagation through time, 32 steps), GAE [3] (\(\lambda=0.95\)), and separate extrinsic and intrinsic value heads (\(\gamma=0.995\) and \(0.99\)). Other settings: clip 0.2, a target KL of 0.03, entropy annealed from 0.01 to 0.002, and learning rate \(3\!\times\!10^{-4}\) decayed linearly to 15 %. The asymmetric critic [4] sees privileged ground truth: pose, keys, doors, the exit and enemies. The actor rejects any input that is not in the official observation, so nothing privileged reaches the submission.

Scorer-aligned reward. The extrinsic stream mirrors the four scoring categories. It rewards the exit (10, plus bonuses for remaining health and time), keys and unlocks (2 each), doors (0.3), first visits to true engine sectors (0.2, capped at 4) and kills (0.3, capped at 4). It penalises damage taken, death (−3), time and stagnation. The caps keep finishing a level worth more than farming kills or wandering. The intrinsic stream is an episodic count bonus over a 128-unit grid [6]. It ignores spinning in place and fades to zero by 70 % of training.

Procedural map factory and curriculum. We had no dataset, so we wrote a UDMF level generator, following the procedural-generation approach to generalisation [7]. It builds room graphs with corridors, doors, one to three key-and-lock chains, and either a switch exit or a walk-over exit. A solver checks every level before use, and an “uneven” variant varies floor heights. Freedoom levels add hand-made geometry. A Director samples the scenario families whose success rate is near 50 % and unlocks harder levels as the agent improves. It also replays failed seeds as fresh “nemesis” episodes, in the spirit of prioritised level replay [9], and ends on vanilla rules at skill 3. Each episode is mirrored left–right at random, with ray \(i\mapsto(64-i)\bmod 64\), which doubles the variety of layouts.

Compute. Training ran on two laptops with RTX 3050 GPUs, using CPU worker processes for the environments. The main run reached 62 M decisions (about 250 M game tics, 199 k episodes) in 11.5 h. A second run continued from that run’s checkpoint with a damage-dealt reward and more practice on switch exits (aim).

4 Experiments

Protocol. Every policy plays the same held-out suite through the real submission/agent.py: 240 generated maps that were never used in training, with plain and uneven geometry, plus 3 Freedoom maps, across tiers 1–4 (249 episodes, fixed seeds). Our local scorer mirrors the official categories and weights the tiers 1:2:3:4 (the official weights are hidden). Intervals come from a paired bootstrap that resamples maps within each tier.

Scaling and fine-tuning. Training from 40.5 M to 62 M decisions raises the weighted score by 8.6 points, and the 95 % CI excludes zero. The largest gain is in tier 3: the agent reaches the exit 14 points more often after collecting keys and unlocking doors. The two later runs are statistically tied (Δ 0.9, CI −8.3 to 9.7). The aim run is ahead on exploration and the gauntlet, and the main run is ahead on progression. On a second set of 249 new episodes the aim run led 40.5 M by only 3.3 (CI −4.3 to 10.8) and tied both final checkpoints; we submit it.

Does the memory help? Both kinds of memory matter. Removing all state makes the agent forget where it has been, and its exit rate falls from about 70 % to 12–28 %. Zeroing only the slot readout, while keeping the GRU, still costs about 10 points, and the CI excludes zero. The loss is largest in exploration and progression and almost absent in pure combat, which is the pattern expected if the slots store places. The decoding method matters little, and we submit sampling at T = 0.5, which avoids the loops that greedy decoding can fall into.

Deployment. All of BBB’s actions come from the network. The code around it only checks input and output shapes and presses nothing for one decision if an exception occurs. The weights are 4.3 MB. A decision takes under 1 ms on average on one CPU thread, against a budget of 40 ms, so we use the CPU even when a GPU is offered.

5 Limitations and future work

BBB’s odometry drifts over long episodes, so anchors are approximate. Door and key colours cannot be observed, so the memory stores “a locked door” rather than “the red door”. In a 240-map test at 40.5 M, exit rates for walk-over exits are 61–100 % but only 31–52 % for switch exits: pressing USE against the right wall is the main failure. Tier 4 remains hard, with deaths in 36–41 % of episodes, and the agent kills only 15 % of enemies. Next steps: a hierarchical manager–worker policy and odometry loop closure.
